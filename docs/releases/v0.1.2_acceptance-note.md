# Mystery Agent Lab v0.1.2 验收与版本说明

## 1. 版本目标

v0.1.2 的目标是增强 CLI 可玩性与调查过程可追踪性，在不扩大到 AI 自动推理、剧本生成、后台管理等方向的前提下，补齐玩家调查过程中的“历史回看”和“调查轮次管理”能力。

本版本核心定位：

- 支持 NPC 问答历史记录与展示；
- 支持调查轮次机制，帮助玩家按阶段推进调查；
- 支持当前轮调查摘要；
- 支持关闭当前轮并开启下一轮；
- 支持查看所有调查轮状态；
- 保持当前架构边界清晰，不引入过度设计。

---

## 2. 已完成功能

### 2.1 NPC 问答历史记录链路

已完成 NPC 问答记录链路打通：

```text
CLI ask
  -> NPCInteractionService.ask_npc(...)
  -> GameRuntime.record_question(...)
  -> NPCAgent / responder.answer(...)
  -> GameRuntime.record_npc_answer(...)
  -> GameState.question_history / answer_history
```

实现效果：

- 玩家每次询问 NPC 后，问题会进入 `question_history`；
- NPC 回答会进入 `answer_history`；
- 问题与回答通过 `question_id` 关联；
- 不再引入 `qa_history` 这种重复事实来源；
- `GameRuntime` 继续作为状态变更入口。

### 2.2 `/history` 问答历史命令

新增命令：

```text
/history
history
```

展示内容：

- 历史问答顺序；
- NPC 名称与 ID；
- 玩家问题；
- NPC 回答；
- 无回答时显示兜底信息。

示例：

```text
【问答历史】

[1] 询问 NPC：程曼（npc_pharmacist）
玩家：你是谁？
NPC：我是程曼，诊所的药剂师。
```

## 3. 调查轮次机制

### 3.1 新增 InvestigationRound 模型

新增调查轮次模型，用于表达玩家调查阶段：

```text
InvestigationRound
- round_id
- round_no
- status
- question_ids
- started_at
- closed_at
```

状态枚举：

```text
InvestigationRoundStatus.OPEN
InvestigationRoundStatus.CLOSED
```

### 3.2 GameState 扩展

`GameState` 新增：

```text
active_round_id
investigation_rounds
```

保留：

```text
question_history
answer_history
current_round
```

说明：

- `question_history` / `answer_history` 是事实记录；
- `investigation_rounds` 是调查阶段索引；
- `question_ids` 只保存问题 ID，不复制问题正文；
- `current_round` 当前仍保留原语义，可继续表示已使用提问次数。

### 3.3 Runtime 行为

已完成：

- `GameRuntime.start()` 自动创建第 1 轮调查；
- `GameRuntime.record_question()` 将问题绑定到当前调查轮；
- `GameRuntime.close_current_round()` 关闭当前轮并开启下一轮；
- OPEN 轮次 `closed_at` 为 `None`；
- CLOSED 轮次设置 `closed_at`。

## 4. CLI 调查轮次命令

### 4.1 `/review` 当前调查轮摘要

新增命令：

```text
/review
review
summary
```

展示当前调查轮：

- 调查轮次；
- 轮次状态；
- 本轮提问次数；
- 本轮回答次数；
- 已发现线索数；
- 当前总提问次数；
- 本轮已询问 NPC；
- 本轮问答明细。

示例：

```text
【当前调查轮摘要】
调查轮次：第 1 轮
轮次状态：OPEN
本轮提问次数：2
本轮回答次数：2
已发现线索数：3
当前总提问次数：2

【本轮已询问 NPC】
- 程曼（npc_pharmacist）：1 次
- 陆青（npc_photographer）：1 次
```

### 4.2 `/close-round` 关闭当前调查轮

新增命令：

```text
/close-round
close-round
close
```

行为：

- 调用 `GameRuntime.close_current_round()`；
- 关闭当前调查轮；
- 自动开启下一轮；
- 输出当前轮关闭与下一轮开启信息。

示例：

```text
【关闭调查轮】
第 1 轮已关闭。
第 2 轮已开启。
```

### 4.3 `/rounds` 查看调查轮次列表

新增命令：

```text
/rounds
rounds
```

展示所有调查轮：

- 轮次编号；
- 轮次状态；
- 本轮提问次数；
- 当前轮标记。

示例：

```text
【调查轮次列表】
第 1 轮：CLOSED，提问 2 次
第 2 轮：OPEN，提问 1 次（当前）
```

## 5. 架构决策

### 5.1 不新增 qa_history

本版本明确不引入：

```text
qa_history
QAHistoryItem
```

原因：

- `question_history` 和 `answer_history` 已经是事实记录；
- `qa_history` 会成为重复数据源；
- 后续存档、回放、统计、轮次归档会出现一致性问题；
- 展示层需要的是 View，不应该落入核心状态。

### 5.2 GameRuntime 继续作为状态变更入口

涉及以下行为的逻辑仍由 `GameRuntime` 管理：

- 角色合法性校验；
- 提问轮次限制；
- 记录问题；
- 记录 NPC 回答；
- 绑定问题到调查轮；
- 关闭调查轮；
- 开启新调查轮；
- 更新状态时间。

`NPCInteractionService` 只负责应用编排，不直接 append `question_history` / `answer_history`。

### 5.3 CLI 只做读模型与用户交互

CLI 层负责：

- 展示命令；
- 接收输入；
- 调用应用服务 / Runtime；
- 格式化输出。

CLI 不负责：

- 状态规则；
- 回合限制；
- 角色校验；
- 问答记录持久化；
- 调查轮次状态变更细节。

## 7. 手工验收流程

启动游戏：

```bash
python dev/run_cli.py --script snow_inn_murder
```

建议手工流程：

```text
rounds
ask
history
review
close-round
rounds
ask
review
rounds
```

预期结果：

1. 初始 `rounds` 显示第 1 轮 OPEN；
2. `ask` 后，`history` 能看到问答；
3. `review` 显示第 1 轮当前调查摘要；
4. `close-round` 后，第 1 轮 CLOSED，第 2 轮 OPEN；
5. 第二轮 `ask` 后，`review` 只显示第 2 轮内容；
6. `rounds` 显示第 1 轮 CLOSED、第 2 轮 OPEN。

## 8. 本版本不包含的内容

v0.1.2 不包含以下内容：

- AI 自动复盘；
- AI 推理辅助；
- 嫌疑人热度分析；
- 证据充分性判断；
- 按轮次生成自然语言总结；
- 存档文件按调查轮归档；
- 数据库持久化；
- Web 管理后台；
- 剧本上传；
- AI 生成剧本。

这些能力可在后续版本规划。

## 10. 后续版本建议

v0.1.3 可考虑以下方向之一：

1. 会话记录增强：将 `history` / `rounds` 纳入 session recorder；
2. 剧本数据源增强：完善 script repository 抽象与多来源加载；
3. NPC 表现增强：优化回答稳定性、角色边界和上下文控制；
4. 规则与结算增强：增强最终推理评分、线索命中解释和复盘输出；
5. CLI 体验增强：命令帮助、错误提示、交互引导进一步优化。

建议优先选择“会话记录增强”或“剧本数据源增强”，避免过早进入 AI 自动推理。
